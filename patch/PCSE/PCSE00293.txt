# Final Fantasy X HD Remaster [US]
#
#
# Multisampling covers the DISPLAY render target only. The scene is drawn into
# off-screen buffers whose sample count is a hard-coded 4 at 0:0xDDEB0 and
# 0:0xDDF44, so scene geometry stays at 4x whatever this is set to.
#
# Display size, internal resolution and multisampling in ONE file: no offset is
# shared between the three blocks, so unlike the sibling PCSE00283 this title
# needs no second variant file. Every block can be selected on its own or
# together with the others.
#
# PhyreEngine game (module ffx_phyreApp.self), same application framework as
# FFX-2 HD Remaster (PCSE00283) at different offsets. The display config
# (app+0x294: width, height, ..., sample count at +24) is filled by the
# application constructor with immediates and feeds the display render target,
# the three display buffers, the depth surface, sceDisplaySetFrameBuf, the
# viewport / region clip and the game's screen rectangles.
# THE SCENE IS NOT DRAWN INTO THE DISPLAY BUFFERS. PostProcessManager::create
# (0xDE704, called at 0xC031C with config+0 / config+4) stores the display size
# at ppm+0x145C / ppm+0x1460, and the deferred setup 0xDDDF8 builds from it an
# off-screen "PostProcessManager_colorBuffer" texture render target (type byte
# 4 = 4x MSAA, 0xDDEB0) plus "PostProcessManager_depthBuffer" (0xDDF44) and two
# half-size targets; the scene is composited from there onto the display. When
# the low-resolution flag ppm+0x1425 is set the game renders only a 0.75-scaled
# sub-rectangle of that target (960x544 -> 720x408) and samples it back with a
# (0.75, 0.75) "UvScaleBias". @IB is that scale.
#
# INTERNAL SCALE. S = K / 32, K = min(max(32*ib_w/fb_w,16),32): the VFP and NEON
# float immediates only encode multiples of 1/32 in [0.5, 1.0], so K is an
# integer in 16..32. Only ib_w is read; ib_h is ignored and the internal height
# follows fb_h * K / 32. On the native 960x544 framebuffer:
#   IB 960x544 -> K = 32, 960x544 (full resolution, the display is 1:1)
#   IB 720x408 -> K = 24, 720x408 (the game's own internal size: every one of
#                 the 22 @IB lines then re-writes its own original bytes)
#   IB 640x368 -> K = 21, 630x357 (NOT 640x368 - K is truncated)
#   IB 480x272 -> K = 16, 480x272 (half)
# With @FB on as well the ratio is taken against fb_w, so FB 720x408 + IB
# 960x544 clamps to K = 32 (720x408 rendered 1:1) and FB 720x408 + IB 480x272
# renders 472x267. With @IB switched off the game keeps its own 0.75 whatever
# @FB is set to, which is complete on its own: the low-res rectangle is then
# 0.75 * fb.
# The 22 @IB lines are the four viewport / region-clip scale sites (the shared
# function 0xDE796 and its three inlined copies), the seven UvScaleBias literal
# pools of the low-res sampling passes and the two NEON UvScaleBias writers.
# There is nothing else: seg0 holds exactly fifteen 0x3F400000 words (fourteen
# of them these seven pools, the fifteenth at 0xC24EC the (1.0, 0.75) UvScaleBias
# of the unreachable function 0xC2314 - see the report) and no other
# vmov.f32 #0.75 reaches a viewport, a region clip or a texture size.
# Unlike FFX-2 there is no "boost" multiplier on the render scale: each of the
# four scale sites does one vmul.f32 by s4 per component and nothing else
# (0xDE7D4..0xDE7E0, 0xDEB04..0xDEB10, 0xDF342..0xDF34E, 0xE09FC..0xE0A08), so
# there is no second multiply to cap at 1/S. (1.32f DOES exist in this module -
# movw #0xF5C3 + movt #0x3FA8 at 0x3B8308/10, 0x3B8408/10 and 0x3BE28C/90 - but
# all three sit in a tone-curve evaluator beside 0.061, 0.0015 and 1.47 and
# never reach a viewport.) There are also no hard-coded tile-aligned halves of
# the low-res rectangle - the only constant rectangles handed to the viewport /
# region-clip emitters 0x44192 / 0x44232 are the five picture-in-picture
# window clips of 0xC2748..0xC2806 (display coordinates of the config-sized
# target, so they belong to @FB) and the 1280x720 movie and 960x960 / 512x512
# shadow-map clips, which are not display-derived.
#
# SUB-PIXEL NOTE. The scale sites truncate (vcvt.u32.f32) while the UvScaleBias
# carries the exact S, so the rendered rect and the sampled rect agree only when
# fb * K / 32 is an integer. That holds for every fb on 960x544, 640x368 and
# 480x272 and for FB 720x408 with IB 960x544 / 720x408 / 640x368; the single
# exception is FB 720x408 + IB 480x272 (K = 21), which renders 472x267 but
# samples 472.5x267.75 - up to one pixel of the composite edge reads
# uninitialised target.
#
# @MSAA is unchanged from the previous revision of this file and is NOT a
# complete option: its two lines change the DISPLAY render target only (the
# config sample count and the display builder's depth row multiplier). The
# off-screen PostProcessManager colour and depth buffers - the targets the scene
# geometry is actually drawn into - carry their own hard-coded type byte 4
# (movs r0, #4 at 0:0xDDEB0 and 0:0xDDF44), which this block does not touch, so
# selecting "none" or "2x" leaves all scene geometry at 4x multisampling.
# Offsets are for module NID 0x70F290D1 (ffx_phyreApp.self).
