# Final Fantasy X-2 HD Remaster [US]
#
# Internal resolution and multisampling. The display stays at the game's own 960x544: this file has no @FB
# block and never reads the FB setting. A display-size option cannot be added to this file: 24 constants
# of the low-resolution rectangle depend on both the display size and the internal scale, and an offset
# may be patched only once per file.
#
# PhyreEngine game (module ffx2_phyreApp.self, NID 0x0D27CBF3), same framework as FFX HD. The application
# constructor fills the display config (960x544, sample count 4) with immediates. The scene is drawn into an
# off-screen "ColorBuffer" texture target of that size with 4x MSAA and composited onto the display. In the
# scenes where the game sets its low-resolution flag (obj+0x142d) it renders only a 0.75-scaled
# sub-rectangle of that target, 720x408, and samples it back with a (0.75, 0.75) UvScaleBias. Frames are
# paced at 30 FPS.
#
# @IB sets that scale to S = K / 32, K = min(max(32 * ib_w / 960, 16), 32) truncated (the float immediates
# only encode multiples of 1/32). Only the IB width is read; the rendered height is 544 * K / 32. The OSD
# shows the value you selected, not the rounded one.
#   IB 960x544 -> K = 32 -> 960x544 (full resolution)
#   IB 720x408 -> K = 24 -> 720x408 (the game's own setting, nothing visible changes)
#   IB 640x368 -> K = 21 -> 630x357
#   IB 480x272 -> K = 16 -> 480x272 (half; narrower settings also give 480x272)
# With IB switched off the @IB block is skipped and the game is untouched.
# @MSAA sets the sample count of the display target and of the scene target: none, 2x or 4x (4x is the
# game's own). The engine derives every colour surface, depth surface and fragment-program mode from them.
# 2x is a mode the shipped game never uses; its depth layout is corrected here (see the @MSAA block).
#
# Known limits:
# - IB changes only the low-resolution scenes. Scenes the game already draws at 960x544 (flag clear) keep
#   their full resolution at every IB setting.
# - Some passes split the rectangle into two halves on the 32 px tile grid. The game's constants
#   (720 -> 352, 408 -> 192) are read as half the rectangle rounded down to 32 px. The other rule that fits
#   them, 32 * ceil((W - 32) / 64), differs by one tile when W mod 64 > 32 (e.g. W = 630).
# - The vertical split pass cannot put its split lower than y = 224 (16-bit immediate), so at IB widths of
#   930 and more its halves are 224 / 303 or 224 / 320 instead of centred. They still cover the rectangle.
# - The map 56 split pass leaves the last W mod 64 pixels of the rectangle in neither half, as the game
#   does natively (16 px); that is 32 px at IB 480x272, 54 px at IB 640x368 and at most 62 px (IB 510..539).
# - Above IB 720 wide the "BrokenScreenEffect" capture texture grows with S, up to 960x544 (+0.87 MiB).
#   The engine takes it from its GPU heaps when the effect first binds it. Whether they always have room
#   is not established; if they do not, the bind returns out-of-memory.
# Played on hardware at IB 960x544 with MSAA 4x without problems (before the wipe pass of maps 297..305
# was corrected to keep its strip count; that pass was not checked).
# At IB 720x408 with MSAA 4x, 27 of the 54 patched sites differ from the game's bytes: 20 produce the same
# values with other instructions, 2 are the wipe terminator (391 instead of 384; the same strips are
# drawn), and 5 are 2x-only lines that 4x never executes.
