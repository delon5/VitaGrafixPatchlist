# Corpse Party: Blood Drive [US]
#
# Unity 4.3.7p4 player (UnityPlayer_437_Release) with the game's C# AOT-compiled into the
# same module (Assembly-CSharp images: Scene.BonusMenu.BinauralVoice, NameTagListMenu/Student,
# EndingListScreen/Chapter, tk2d, UniLua; trophy set NPWR09002). The player code is ARM (A32),
# not Thumb: every line below is an ARM encoding.
#
# Rendering: GfxDevicePSP2 draws the scene straight into three 960x544 linear display buffers
# (stride 960) with 2x multisampling (QualitySettings antiAliasing = 2 -> MSAA_DOWNSCALE colour
# surfaces, 2x render targets, one shared tiled DF32M_S8 depth/stencil surface of 960x1088
# samples: 32-bit float depth plus a separately allocated 8-bit stencil block); there is no
# off-screen scene target, so @FB is also the render resolution and @IB does not apply.
# Surface memory comes from the 104 MB "GRAPHICS - video heap" through the generic surface
# allocator 0x1EC5C, which sizes every block from the requested width/height (rounded up to
# powers of two: 4 MB per 960x544 colour buffer, 8 MB for the 2x depth surface) plus, for the
# depth surface, a stencil block of align32(sample width) x align32(sample height) bytes
# (0x1F0BC: 1 MB at 2x 960x544).
# Pacing: the sceGxmDisplayQueueAddEntry callback (0x17DA4) calls
# sceDisplayWaitSetFrameBufMulti(2) when QualitySettings vSyncCount is 2 (the game's setting),
# then sceDisplaySetFrameBuf(NEXTFRAME) and sceDisplayWaitSetFrameBuf: 30 FPS. Application.
# targetFrameRate is stored but never enforced by this player; Time.deltaTime is taken from the
# real-time clock (TimeManager 0xA9D20) unless a script sets Time.captureFramerate.
#
# @FB   every back-buffer size, Screen.width/height (the display size handed to
#       sceDisplaySetFrameBuf), the viewports set on the back buffer, the common-dialog render
#       target and the movie player's full-screen rect. For widths that are not a multiple of
#       64 (720, 480) the back buffers get a 768 / 512 pixel stride (display pitch) through a
#       branch into an unreferenced function used as a code cave; 960 and 640 need no cave.
#       Each back buffer's texture view (sceGxmTextureInitLinear at 0x1C6DC, which takes no
#       stride) keeps the implied stride align(width, 8) = 720 / 480. The engine's own copies
#       and readbacks (0x15510, 0x1601C / 0x160A0) use the surface stride and no path that
#       samples a back buffer through that view is known; a sheared full-screen effect at
#       720x408 / 480x272 would point here.
# @MSAA none / 2x / 4x for the back buffers and every fragment program. 4x is only applied
#       when fb_h <= 512 (720x408, 640x368, 480x272), where the depth surface stays at 8 MB or
#       less, the stencil block grows by at most 150 KB and the colour buffers shrink by 6 MB or
#       more. At 960x544 4x would need a 16 MB depth surface and a 2 MB stencil block, about
#       9 MB of video heap beyond the game's own use, which cannot be established, so 4x falls
#       back to 2x there (also when @FB is off).
# @FPS is not provided. The pacing itself is one line (0:0x17DE4, mov r0, #2 -> vblank, the
#       count passed to sceDisplayWaitSetFrameBufMulti) and the engine's clock is real-time,
#       but the game logic is the Assembly-CSharp AOT code, which reaches Time.deltaTime /
#       Time.frameCount only through PLT slots bound at run time, plus UniLua event scripts
#       that are not in the eboot. Whether text, fades, waits and events count frames cannot be
#       settled from the code; if any do, they would run twice as fast at 60 FPS and at 2/3
#       speed at 20 FPS.
#
# Offsets are for module NID 0x959B4DC9 (eboot.bin).

# surface a stride of align(width, 8) pixels (0x1F154: ldr r1, [sp, #8] / add r1, r1, #7 /
# bic r1, r1, #7 / mul r0, r1, r0 = stride bytes); the flip callback hands that stride to
# sceDisplaySetFrameBuf as the pitch, which must be a multiple of 64 (720 -> 768, 480 -> 512).
# Only when fb_w % 64 != 0 (f = 1; f = 0 writes the stock bytes): the add becomes a branch to
# 0xD6B4, the start of an unused back-buffer re-creation function. No branch, call, pointer or
# address construction reaches 0xD654..0xD7DC; the only words naming it are its own jump tables
